# videosai

מערכת שמנתחת סרטון ואומרת מה טוב, מה לא, ומה לתקן קודם - לפי הפלטפורמה שאליה הסרטון מיועד.

הניתוח מקומי לחלוטין (ffmpeg + numpy), בלי העלאה לשרת ובלי מפתחות API. הפלט הוא ציון 0-100,
פירוט לפי שש קטגוריות, רשימת ממצאים עם המלצה קונקרטית לכל אחד, והצעות לפריים שיעבוד כתמונה ראשית.

```
דוח ניתוח וידאו: clip.mp4
פלטפורמה: טיקטוק | ציון כולל: 75.5/100 (C)

  #######...  70.8  פתיח (3 השניות הראשונות)
  #######...  66.5  קצב ועריכה
  ######....  59.0  אודיו
  #########.  85.5  איכות תמונה
  #########.  94.0  פורמט ומסגור
  ########## 100.0  אורך הסרטון

3 התיקונים החשובים ביותר:
  1. האודיו חלש ב־15.9 dB - העוצמה המשוקלטת היא -29.9 LUFS מול יעד של -14.0 LUFS.
     מה לעשות: נרמל ל־-14.0 LUFS (למשל ffmpeg loudnorm) לפני העלאה.
  2. הסרטון נפתח ב־1.6 שניות של שקט - אין קול בהתחלה, וזה בדיוק החלון שבו הצופה מחליט אם להישאר.
     מה לעשות: חתוך את השקט בהתחלה כך שהמשפט הראשון יישמע בתוך 0.3 שניות.
  3. הקצב איטי לפלטפורמה - 6 חתכים לדקה, כשהטווח המומלץ לטיקטוק הוא 12–90.
     מה לעשות: הדק את העריכה: הורד מילות מעבר, נשימות והתחלות משפט שלא מוסיפות.

מה לא עובד:
  ! יש שוט קפוא של 6.8 שניות - מ־0:06.2 הפריים כמעט לא משתנה, וזו נקודה טיפוסית לנשירה.
  i אין חתך אחד בפתיח - 3 השניות הראשונות הן שוט אחד רצוף, מה שמקשה על שמירת קשב בפורמט קצר.

מה עובד טוב:
  + אורך מתאים - 20.6 שניות, בתוך הטווח המומלץ לטיקטוק.
```

## התקנה

דרוש Python 3.10+ ו-FFmpeg (גם `ffmpeg` וגם `ffprobe`) ב-PATH.

```bash
# ffmpeg
sudo apt install ffmpeg        # Debian/Ubuntu
brew install ffmpeg            # macOS

pip install -e .               # מהתיקייה של הפרויקט
pip install -e ".[server]"     # כולל השרת (FastAPI + uvicorn)
pip install -e ".[dev]"        # כולל pytest
```

## שימוש

```bash
videosai analyze clip.mp4                                   # דוח בעברית לטרמינל, יעד ברירת מחדל: טיקטוק
videosai analyze clip.mp4 -p youtube -l en                  # פלטפורמה ושפה אחרות
videosai analyze clip.mp4 -f json -o report.json            # JSON לצינור עיבוד
videosai analyze clip.mp4 -f html -o report.html \
    --thumbnails covers/                                    # דוח HTML עם פריימים מוצעים לתמונה ראשית
videosai analyze *.mp4 --fail-under 70                       # קוד יציאה 1 אם הציון נמוך מ-70 (שימושי ב-CI)
videosai platforms                                          # רשימת הפלטפורמות הנתמכות
```

## הרצה כשרת

```bash
videosai serve                                  # http://127.0.0.1:8000
videosai serve --host 0.0.0.0 --port 8000 \
    --max-upload-mb 256 --workdir /var/lib/videosai
```

בדפדפן: דף העלאה עם בחירת פלטפורמה ושפה, ואחרי הניתוח מתקבל דוח HTML מלא באותו עיצוב, כולל הפריימים
המוצעים לתמונה ראשית. הקובץ שהועלה נמחק מיד לאחר הניתוח (`--keep-uploads` משאיר אותו לצורכי דיבוג),
ותיקיות עבודה ישנות נמחקות אוטומטית אחרי שעה.

| נתיב | מה הוא עושה |
| --- | --- |
| `GET /` | דף העלאה (`?lang=en` לאנגלית) |
| `POST /analyze` | העלאת multipart, מחזיר את דוח ה-HTML |
| `POST /api/analyze` | אותו דבר, מחזיר JSON |
| `GET /api/platforms` | הגדרות הפלטפורמות |
| `GET /healthz` | בדיקת חיים, כולל האם ffmpeg זמין |
| `GET /docs` | תיעוד ה-API (OpenAPI) |

```bash
curl -X POST http://127.0.0.1:8000/api/analyze \
     -F "file=@clip.mp4" -F "platform=tiktok" -F "thumbnails=true"
```

הניתוח רץ ב-thread pool עם תקרה של שתי הרצות במקביל (ffmpeg הוא צוואר הבקבוק), יש מגבלת גודל להעלאה,
ובדיקת סיומת וסוג קובץ לפני שמתחילים לעבוד. לפרודקשן: הרצה מאחורי reverse proxy עם TLS, והגדלת
המקביליות לפי מספר ה-vCPU.

מ-Python:

```python
from videosai import analyze_video, to_markdown

report = analyze_video("clip.mp4", platform="reels")
print(report.score, report.grade)

for finding in report.priorities(3):
    print(finding.code, finding.penalty)

open("report.md", "w").write(to_markdown(report, lang="he"))
```

## מה נמדד

| קטגוריה | מה נבדק | דוגמאות לממצאים |
| --- | --- | --- |
| פתיח (3 שניות) | שקט בפתיחה, תנועה בפריים מול הממוצע בסרטון, חתך בפתיח, בהירות וחדות | `HOOK_DEAD_AIR`, `HOOK_STATIC`, `HOOK_DARK_OPEN` |
| קצב ועריכה | חתכים לדקה מול הטווח של הפלטפורמה, השוט הקפוא הארוך ביותר | `PACING_SLOW`, `PACING_FROZEN_SHOT`, `PACING_FRANTIC` |
| אודיו | עוצמה משוקלטת (LUFS), שיא אמיתי, שתיקות ארוכות, טווח דינמי, תדר דגימה | `AUDIO_MISSING`, `AUDIO_QUIET`, `AUDIO_CLIPPING`, `AUDIO_DEAD_GAPS` |
| איכות תמונה | חדות (Laplacian), חשיפה, פיקסלים שרופים, ניגודיות, רוויה, קטעים חשוכים | `VISUAL_SOFT_FOCUS`, `VISUAL_UNDEREXPOSED`, `VISUAL_DARK_SEGMENTS` |
| פורמט ומסגור | יחס גובה-רוחב, רזולוציה, fps, ביטרייט לפיקסל, אזורי הממשק של הפלטפורמה | `FRAMING_ASPECT`, `FRAMING_LOW_RES`, `FRAMING_SAFE_ZONE_BOTTOM` |
| אורך | האורך מול הטווח שעובד בפלטפורמה ומול המגבלה הקשה שלה | `DURATION_SHORT`, `DURATION_LONG`, `DURATION_OVER_LIMIT` |

איך מחושב הציון: כל קטגוריה מתחילה ב-100, וכל ממצא מוריד ניקוד לפי מידת החריגה (ממצא חמור יותר =
עונש גדול יותר). הציון הכולל הוא ממוצע משוקלל של הקטגוריות, והמשקלים משתנים לפי הפלטפורמה - בפורמט
קצר הפתיח מקבל 28% מהציון, ובסרטון ארוך האודיו מקבל את המשקל הגבוה.

הפלטפורמות הנתמכות: `tiktok`, `reels`, `shorts`, `youtube`, `instagram_feed`, `generic`. לכל אחת יש
יחס מסך יעד, רזולוציה מינימלית, טווח אורך מומלץ, יעד עוצמת אודיו, טווח חתכים לדקה ואזורי ממשק.

## מבנה הקוד

```
videosai/
  media.py          עטיפה ל-ffmpeg/ffprobe: מטא-דאטה, דגימת פריימים, זיהוי חתכים, מדידת אודיו
  features.py       פיצ'רים לכל פריים: בהירות, ניגודיות, רוויה, תנועה, חדות, עומס באזורי הממשק
  analyzers/        קטגוריה אחת לכל קובץ, כל אחת מחזירה ציון + ממצאים
  platforms.py      מה נחשב "טוב" בכל פלטפורמה
  messages.py       קטלוג ההודעות בעברית ובאנגלית (הליבה מייצרת קודים בלבד)
  render.py         טקסט / Markdown / JSON / HTML עצמאי
  engine.py         הצינור: מודדים פעם אחת, מריצים את כל האנלייזרים
  server.py         שרת FastAPI: דף העלאה, דוח HTML ו-API ב-JSON
  cli.py            שורת הפקודה
```

הפרדה חשובה: האנלייזרים מייצרים **קודים** (`HOOK_DEAD_AIR`) ולא טקסט. הטקסט מיוצר ברינדור מתוך
`messages.py`, ולכן אותו דוח נראה נכון בעברית ובאנגלית, ואפשר להוסיף שפה בלי לגעת בלוגיקה.

להוספת בדיקה חדשה: קובץ ב-`analyzers/` שמחזיר `CategoryResult`, רישום ב-`analyzers/__init__.py`,
משקל בפלטפורמות, ורשומה ב-`CATALOG` לכל קוד חדש.

סרטון תקין, סרטון חשוך ללא פסקול, סרטון עם אודיו חלש וסרטון שנפתח בשקט - ומוודאות שכל בעיה מזוהה.

## מגבלות

הניתוח הוא של האותות הטכניים והעריכתיים, לא של התוכן עצמו. המערכת לא יודעת מה אמרת, אם הבדיחה מצחיקה
או אם הנושא מעניין. היוריסטיקות מכוילות לפורמט מדבר-למצלמה ולתוכן קצר; סרטון קולנועי אפל בכוונה
יקבל התראה על חשיפה, וסרטון מדיטציה יקבל התראה על קצב. הציון הוא כלי עזר לפני העלאה, לא שיפוט.

## מה עוד אפשר לבנות ליוצרי תוכן

הניתוח הזה הוא השכבה הראשונה. מכאן יש כמה כיוונים, מהזול והמדויק אל היקר והחכם:

**1. תמלול והוק במילים.** להוסיף Whisper מקומי, ואז לנתח את מה שנאמר ולא רק איך שזה נשמע: קצב דיבור
(מילים בדקה), מילות מילוי, האם המשפט הראשון מבטיח משהו, האם יש קריאה לפעולה בסוף. מכאן קצרה הדרך
להצעות ניסוח חלופיות לשלוש השניות הראשונות ולכתוביות מסונכרנות בפורמט SRT/ASS.

**2. בדיקת כתוביות ואזורי ממשק ברמת הטקסט.** OCR על הפריימים כדי לזהות טקסט קטן מדי, טקסט שנחתך,
או כתובית שיושבת מתחת לכפתורים של הפלטפורמה. היום המערכת מזהה רק "עומס גרפי" באזורים האלה.

**3. בחירת תמונה ראשית והשוואת גרסאות.** דירוג הפריימים קיים; מעליו אפשר לבנות זיהוי פנים ומבט,
בדיקת קריאות של הכיתוב על התמונה, ויצירת שתי גרסאות להשוואה בפועל מול הנתונים בפלטפורמה.

**4. התאמה אוטומטית לכמה פלטפורמות.** אותו סרטון מקור, פלט אחד לכל יעד: חיתוך חכם ל-9:16 שעוקב אחרי
הנושא, נרמול עוצמה ליעד של כל פלטפורמה, קיצור לטווח שעובד שם, וגרסה שקטה עם כתוביות לפיד שמתנגן בלי קול.

**5. לופ מול הנתונים האמיתיים.** חיבור ל-API של הפלטפורמות, מתיחת עקומת הצפייה מול הציונים שהמערכת
נתנה, וכיול המשקלים והספים לפי מה שבאמת עבד בערוץ הספציפי. זה מה שהופך יוריסטיקה לתחזית.

**6. שכבת מודל שפה מעל הממצאים.** הממצאים הם נתונים מובנים, ולכן אפשר להזין אותם למודל שיכתוב סיכום
בשפה של היוצר, יציע כותרת ותיאור, יציע רשימת שוטים לסרטון הבא, או ינהל מעקב שיפור לאורך זמן.

**7. שילוב בזרימת העבודה.** בדיקת CI לפני העלאה (`--fail-under` כבר קיים), תוסף לעורך, ניטור תיקיית
Dropbox/Drive, ודשבורד שמראה מגמות לאורך סרטונים - איפה הערוץ משתפר ואיפה נסחב.

**8. השרת כשירות.** המצב הנוכחי הוא שירות של מכונה אחת: בקשה נכנסת, ffmpeg עובד, דוח יוצא. הצעד הבא
הוא תור עבודות (Redis/RQ) עם עדכון התקדמות, אחסון אובייקטים לקבצים ולפריימים, חשבונות משתמש והיסטוריית
סרטונים - וזה גם מה שיאפשר להריץ את המודלים הכבדים (תמלול, OCR) בלי לחסום את הבקשה.

## English summary

`videosai` analyzes a video file locally with FFmpeg and numpy and returns a scored report: what works,
what does not, and what to fix first, tuned per platform (TikTok, Reels, Shorts, YouTube, Instagram
feed). Six categories are measured - hook, pacing, audio, image quality, framing and duration - each
producing stable finding codes that render as text, Markdown, JSON or a standalone HTML report in
Hebrew or English.

```bash
videosai analyze clip.mp4 --platform tiktok --lang en
videosai analyze clip.mp4 -f html -o report.html --thumbnails covers/
videosai serve --host 0.0.0.0 --port 8000     # browser upload page + JSON API
```
